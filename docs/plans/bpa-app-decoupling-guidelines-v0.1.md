# BPA App 解耦设计准则 v0.1

> 文档类别：BPA App 架构计划与开发准则。
> 记录时间：2026-08-05。
> 实现状态：目标边界，尚未全部平台化。

## 1. 目标与定义

BPA 提供可复用的运行机制，BPA App 组合领域能力、业务规则和业务界面。App 不应把临时脚本、浏览器补丁、数据库、模型、通知和 UI 串成只能整体运行的一条长链。

```text
App Manifest
├── Trigger 配置
├── Workflow 组合
├── 领域 Node 与 Adapter
├── 领域数据库与 migration
├── 规则和模型版本
├── Domain API
├── 业务面板
└── Delivery 配置
```

## 2. 平台与 App 职责

| 边界 | BPA 平台负责 | App 负责 |
| --- | --- | --- |
| 触发 | Trigger 状态机、租约、幂等和审计 | 触发条件与固定 Workflow 版本 |
| 执行 | Node 调度、超时、恢复和证据 | 领域步骤和回退策略 |
| 浏览器 | Page Binding、Control Lease、就绪和释放 | 页面语义与领域读取逻辑 |
| 数据 | FactEnvelope、Dataset、血缘和版本 | 领域 Schema、身份映射和质量口径 |
| 计算 | 纯节点执行、版本冻结和重放 | 算法、阈值和策略版本 |
| 事件 | 唯一键、迟滞、状态迁移和审计 | 定义业务事件 |
| 通知 | 渠道发送、回执、限流和幂等 | 对象、模板、升级和启用策略 |
| 展示 | 会话、安全头和通用组件 | 员工领域视图 |
| AI | Authoring、诊断和 Assistance | 不作为生产运行依赖 |

App Manifest 声明组合、版本和权限，但不包含数据库凭证、任意 SQL、Cookie 或自由执行命令。

## 3. 三个平面分离

### 控制面

负责 Trigger、Workflow Run、租约、浏览器控制权、状态机和审计。控制面决定是否运行，但不偷偷修改领域事实。

### 数据面

负责从浏览器、数据库或 API 读取来源，发布不可变事实并运行确定性计算。数据面不决定通知对象，也不直接操作业务 UI。

### 体验面

负责业务查询、展示和人工评审。面板消费 Domain API，不直接控制浏览器、不持有数据库自由写权限，也不因页面刷新启动采集。

## 4. 领域数据链路

```text
Source Adapter
→ Normalized Facts
→ Immutable Dataset Version
→ Pure Computation
→ Domain Event
→ Delivery
```

每层都可以独立重跑，并通过稳定 ID、版本和 digest 关联。上游失败不删除已发布事实，下游失败不要求重新操作浏览器。

### 来源采集

- 只处理特定来源和语义。
- 不内联模型、风险或通知。
- 逐项持久化并返回完整、部分或阻断摘要。

### 事实标准化

- 去重、身份和时间口径显式版本化。
- 不保存无关敏感原始数据。
- 新鲜度、完整性和映射置信度不混入业务严重度。

### 纯计算

- 固定算法、配置和 Dataset 版本。
- 相同输入产生相同结果。
- 不访问浏览器、不发送消息、不修改外部系统。

### 领域事件与 Delivery

- 业务风险和数据质量使用不同事件类型。
- 范围、策略版本和业务键保证事件唯一。
- Delivery 只消费已持久化待发送事件。
- 通知凭证不进入采集或计算进程。
- 外部写入有独立幂等键、回执和不确定结果策略。

## 5. 浏览器能力解耦

| 概念 | 回答的问题 |
| --- | --- |
| Page Binding | 使用哪个浏览器、Profile、Tab、店铺和页面角色 |
| Control Lease | 当前谁拥有操作权 |
| Capability | Node 能读取或修改哪些语义 |
| Effect Confirmation | 是否允许发布、改库存或发送外部结果 |

以下能力进入 Browser Runtime，而不是由每个 Adapter 重复实现：

- 页面、店铺和登录状态稳定窗口。
- 抽屉、浮层、分页和虚拟列表标准状态机。
- 有界局部恢复和失败率熔断。
- 标签页归属、关闭和基准页面恢复。
- 跨 RPA 控制租约或冲突检测。
- 脱敏动作轨迹、DOM 摘要、截图和诊断包。

领域 Adapter 只定义页面语义、解析规则和允许的受控动作。

## 6. 存储与权限

- BPA Core 保留协议和运行状态持久化。
- 每个 App 使用独立领域数据库、角色、migration 和备份策略。
- Workflow 不获得数据库 URL、自由 SQL、任意 HTTP 或任意文件路径。
- 服务 Node 通过精确 manifest 和受限 IPC 调用 App。
- 面板默认只读；人工评审使用窄写入接口、CSRF 和审计。
- 通知、迁移、运行时和诊断角色分别最小授权。

## 7. UI 与运行时

业务面板只展示需要处理、风险、数据质量、当前运行、最近结果、新鲜度和自动计划。Workflow、Node、Adapter、Browser Session、Dataset ID 和 Evidence Digest 默认隐藏。

开发者控制台独立展示 Runtime、Page Binding、Control Lease、执行时间线、数据集、证据、诊断包和 Developer Capture。

业务面板不是调度控制面；页面加载、刷新和筛选不得直接启动采集。

## 8. AI 与生产

AI 可以生成待审查资产、解释诊断包、辅助评审，并在严格条件满足时执行监督性恢复。

AI 不应成为以下能力的唯一实现：

- 周期触发和事件消费。
- 幂等、租约和 fencing。
- 数据同步、预测和风险迁移。
- 已批准模板的正常通知。
- 崩溃恢复和运行终态回收。

## 9. 版本与发布

每次运行计划冻结 Trigger、Workflow、Node、Adapter、Dataset、算法、策略和 Delivery 模板版本。

发布 Workflow、扩大浏览器写权限、启用通知和修改库存仍是独立高影响动作，不能因 App 已获得页面绑定而自动授权。

## 10. 反模式

- UI API 直接执行浏览器脚本。
- 一个 Node 同时交互、解析、持久化、建模和通知。
- 每次库存采集都无条件同步订单。
- 用 Codex 自动任务代替 App Scheduler。
- 用数据库租约代表浏览器独占。
- 用状态 JSON 直接决定重复触发。
- 将渠道 `unknown` 聚合成商品缺货事件。
- 因单商品失败丢弃已持久化事实。
- 让业务员工配置 Session、Dataset ID 或内部协议。
- 把单一 App 的页面补丁直接定义为平台通用能力。

## 11. 通用化判断标准

能力进入 BPA 平台前应同时满足：

1. 至少两个 App 或独立场景存在相同语义需求。
2. 能定义稳定输入、输出、错误和权限边界。
3. 不包含具体店铺、商品、页面文案或业务阈值。
4. 可以使用夹具和纯测试验证。
5. 失败不会隐式扩大外部效果。

否则应先保留在 App Adapter 或领域服务中，经过复用验证后再上提。

## 12. App 检查清单

### 触发与执行

- 是否只有一个生产调度控制面？
- 停止 AI 后是否仍能自动运行？
- 是否有幂等键、租约、fencing 和明确终态？

### 数据

- 采集、事实、计算、事件和通知是否可独立重跑？
- 是否使用不可变 Dataset 和版本化血缘？
- 部分成功是否准确保留和展示？

### 浏览器

- Page Binding 和 Control Lease 是否分离？
- 是否有开始、恢复、标签页回收和释放闭环？
- 是否区分瞬时未就绪、登录失效和结构变化？

### 产品与安全

- 业务面板是否只展示领域结果？
- 高影响效果是否单独授权和审计？
- AI、Workflow 和页面内容是否都无法扩大权限？

只有这些边界明确后，App 才适合扩展到多店铺和长期无人值守运行。
